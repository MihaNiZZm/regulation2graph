# Workflow Net: Формальная модель бизнес-процессов

## 1. Введение

**Workflow Net** — это специализированный подкласс сетей Петри (Petri Net), разработанный для моделирования бизнес-процессов. Был формализован Вилом ван дер Аальстом (Wil van der Aalst) в 1990-х годах.

### Почему Workflow Net?

| Критерий | Текущая модель (Event-Gateway) | Workflow Net |
|----------|-------------------------------|--------------|
| Формальная семантика | Частичная | Полная (математическая) |
| Анализ корректности | Нет | Да (soundness, deadlock detection) |
| Исполняемость | Ограниченная | Полная (симуляция через токены) |
| Стандартизация | Нет | Да (ISO, PNML формат) |
| Инструментарий | Нет | pm4py, ProM, CPN Tools |

## 2. Базовые концепции сетей Петри

### 2.1. Компоненты

Сеть Петри состоит из трёх типов элементов:

```
┌─────────────────────────────────────────────────────────────┐
│                      СЕТЬ ПЕТРИ                             │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   ○ Place (Место)      — состояние, условие, ресурс        │
│   ■ Transition (Переход) — действие, событие, активность   │
│   → Arc (Дуга)         — связь между Place и Transition    │
│   ● Token (Фишка)      — маркер текущего состояния         │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 2.2. Визуальная нотация

```
    ○ — Place (круг/эллипс)
    ■ — Transition (прямоугольник/квадрат)
    ● — Token (точка внутри Place)
    → — Arc (стрелка)
```

### 2.3. Правила выполнения (Firing Rules)

**Переход (Transition) может сработать (fire), если:**
1. Все входные Places содержат хотя бы один Token
2. После срабатывания: токены удаляются из входных Places и добавляются в выходные

**Пример:**
```
До срабатывания:          После срабатывания:
    ●
   (○)───→■───→(○)        (○)───→■───→(○)
   p1      t1    p2        p1      t1   ●p2
```

## 3. Workflow Net: Специализация для бизнес-процессов

### 3.1. Определение

**Workflow Net** — это сеть Петри с дополнительными ограничениями:

1. **Один начальный Place (i)** — source, без входящих дуг
2. **Один конечный Place (o)** — sink, без исходящих дуг
3. **Связность** — каждый узел лежит на пути от i к o

```
     ┌──────────────────────────────────────────┐
     │            WORKFLOW NET                  │
     │                                          │
●───(○)───→■───→(○)───→■───→(○)───→■───→(○)    │
     i      t1    p1    t2    p2    t3    o     │
   start                                 end    │
     │                                          │
     └──────────────────────────────────────────┘
```

### 3.2. Семантика элементов в контексте бизнес-процессов

| Элемент Petri Net | Значение в Workflow | Пример |
|-------------------|---------------------|--------|
| Place | Состояние процесса | "Заявка подана", "Документ на проверке" |
| Transition | Действие/Активность | "Подписать договор", "Проверить документ" |
| Token | Экземпляр процесса (case) | Конкретная заявка №123 |
| Arc | Поток управления | Порядок выполнения |

### 3.3. Soundness (Корректность)

Workflow Net называется **sound**, если:

1. **Завершаемость:** Из начального состояния всегда можно достичь конечного
2. **Отсутствие deadlock:** Нет "застревания" посередине
3. **Отсутствие лишних токенов:** В конце только один токен в конечном Place

Это позволяет **автоматически проверять** корректность модели!

## 4. Паттерны управления потоком

### 4.1. Последовательность (Sequence)

Самый простой паттерн — действия выполняются одно за другим.

```
●───(○)───→■───→(○)───→■───→(○)───→■───→(○)
   start   t1    p1    t2    p2    t3   end

Текст: "Сотрудник подаёт заявку. Менеджер проверяет. Директор утверждает."
```

**Маппинг на текущую модель:**
- `t1, t2, t3` = Triplet (действия)
- `p1, p2` = промежуточные состояния (НОВОЕ!)

### 4.2. Исключающее ветвление (XOR-split / XOR-join)

**XOR-split:** Выбор одного из нескольких путей (условие "если-то-иначе").

```
                    ■─────→(○)───→■
                   t2a     p2a   t3a
                  /                 \
●───(○)───→■───→(○)                 (○)───→■───→(○)
   start   t1    p1                  p3    t4   end
                  \                 /
                    ■─────→(○)───→■
                   t2b     p2b   t3b

Текст: "Менеджер проверяет заявку.
        Если одобрено — бухгалтер оформляет.
        Иначе — секретарь возвращает."
```

**Как это работает:**
- Place `p1` — точка ветвления
- Из `p1` **только один** переход может сработать (XOR)
- Условие определяет, какой переход активируется
- `p3` — точка слияния (XOR-join)

**Ключевое отличие от текущей модели:**
- Сейчас: `[действие] → [Gateway]` (неправильно!)
- Workflow Net: `[Place/условие] → [Transition/действие]` (правильно!)

### 4.3. Параллельное выполнение (AND-split / AND-join)

**AND-split:** Запуск нескольких действий одновременно.

```
                    ■─────→(○)───→■
                   t2a     p2a   t3a
                  ↗                 ↘
●───(○)───→■───→(○)                 (○)───→■───→(○)
   start   t1    p1                  p3    t4   end
                  ↘                 ↗
                    ■─────→(○)───→■
                   t2b     p2b   t3b

Текст: "После подачи заявки параллельно:
        юрист проверяет документы И бухгалтер рассчитывает бюджет.
        После завершения обоих — директор принимает решение."
```

**Как это работает:**
- Transition `t1` срабатывает и создаёт токены в ОБОИХ местах (p2a и p2b)
- `t2a` и `t2b` могут работать параллельно
- Transition `t4` ждёт токены из ОБОИХ мест (AND-join)

### 4.4. Сравнение XOR и AND

| Паттерн | Split | Join | Токены |
|---------|-------|------|--------|
| XOR (условие) | Один путь из нескольких | Один вход из нескольких | 1 → 1 |
| AND (параллелизм) | Все пути одновременно | Ждать все входы | 1 → N → 1 |

### 4.5. Цикл (Loop)

```
         ┌────────────────────────┐
         ↓                        │
●───(○)───→■───→(○)───→■───→(○)───┤
   start   t1    p1    t2    p2   │
                                  │
         [если ошибка — повторить]│
                                  │
                       ■───→(○)───┘
                      t3   end
```

## 5. Маппинг текущей модели на Workflow Net

### 5.1. Текущие сущности → Workflow Net

| Текущая модель | Workflow Net | Изменения |
|----------------|--------------|-----------|
| `Triplet` | `Transition` | Переименование |
| `Gateway` | Специальные Places или silent Transitions | Рефакторинг |
| — (отсутствует) | `Place` (состояния) | ДОБАВИТЬ |
| `Event → Gateway` | `Place → Transition` | ИСПРАВИТЬ ПОРЯДОК |

### 5.2. Пример трансформации

**Текущая модель (неправильно):**
```
[Подписать договор] ──LEADS_TO──→ [◇ Документ согласован?]
                                          ├── IF_TRUE → [Утвердить]
                                          └── IF_FALSE → [Вернуть]
```

**Workflow Net (правильно):**
```
(p0: start)
    │
    ↓
■ t1: Проверить документ
    │
    ↓
(p1: Документ проверен)
    │
    ├──[если согласован]──→ ■ t2: Подписать ──→ (p2) ──→ ■ t4: Утвердить
    │                                                          │
    └──[если не согласован]──→ ■ t3: Вернуть ──────────────────┘
                                                               │
                                                               ↓
                                                          (p3: end)
```

### 5.3. Ключевое исправление

**Условие — это Place (состояние), не отдельный Gateway!**

```
БЫЛО:   [Действие] → [Условие?] → [Да/Нет]
СТАЛО:  [Состояние] → [Действие А (если Да)]
                    → [Действие Б (если Нет)]
```

Условие — это **guard condition** на Transition, не отдельный узел.

## 6. Структура данных для Workflow Net

### 6.1. Модели Python

```python
from dataclasses import dataclass
from enum import Enum

class PlaceType(Enum):
    START = "start"
    END = "end"
    INTERMEDIATE = "intermediate"

class TransitionType(Enum):
    ACTIVITY = "activity"      # Обычное действие
    SILENT = "silent"          # Невидимый переход (tau)

@dataclass(frozen=True)
class Place:
    """Место в Workflow Net — состояние процесса."""
    id: str
    name: str
    place_type: PlaceType = PlaceType.INTERMEDIATE

@dataclass(frozen=True)
class Transition:
    """Переход в Workflow Net — действие в процессе."""
    id: str
    actor: str
    action: str
    obj: str
    guard: str | None = None  # Условие срабатывания
    transition_type: TransitionType = TransitionType.ACTIVITY

@dataclass(frozen=True)
class Arc:
    """Дуга между Place и Transition."""
    source_id: str
    target_id: str
    label: str = ""  # "Да", "Нет" для условных переходов
```

### 6.2. Схема Neo4j

```cypher
// Места (состояния)
CREATE (:Place {id: "p0", name: "Начало", type: "start"})
CREATE (:Place {id: "p1", name: "Документ проверен", type: "intermediate"})
CREATE (:Place {id: "p_end", name: "Конец", type: "end"})

// Переходы (действия)
CREATE (:Transition {
    id: "t1",
    actor: "Менеджер",
    action: "проверить",
    object: "документ",
    guard: null
})

// Дуги
CREATE (p0)-[:FLOW]->(t1)
CREATE (t1)-[:FLOW]->(p1)
CREATE (p1)-[:FLOW {guard: "документ согласован"}]->(t2)
CREATE (p1)-[:FLOW {guard: "документ НЕ согласован"}]->(t3)
```

## 7. Преимущества перехода на Workflow Net

### 7.1. Для проекта regulation2graph

1. **Корректная семантика условий**
   - Условие проверяется ДО действия, не после
   - Чёткое разделение состояний и действий

2. **Формальная верификация**
   - Можно проверить soundness (достижимость конца)
   - Обнаружение deadlock и livelock

3. **Готовый инструментарий**
   - `pm4py` — анализ и визуализация
   - Экспорт в PNML (стандартный формат)
   - Конвертация в BPMN

4. **Масштабируемость**
   - Естественная поддержка параллелизма (AND-split/join)
   - Вложенные подпроцессы

### 7.2. Для научной работы

1. **Теоретическая база** — десятки лет исследований
2. **Сравнимость** — можно сравнивать с другими работами
3. **Цитируемые источники** — van der Aalst, Murata и др.
